## F-01 · ה-CI אדום, ו-`main` אדום

| | |
|---|---|
| **חומרה** | **חוסם** |
| **ודאות** | **מאומת** (עובדת הכישלון) · **פער מידע** (הסיבה) |
| **קדימות** | **1** |

**הראיה:**
```
gh api repos/.../actions/runs?branch=main
  89c6d51 (#89)  push  success  14 דק׳
  1d3b4aa (#90)  push  success  14 דק׳
  9bef73d (#91)  push  FAILURE   7 דק׳   ← main
  4106418 (ענף)  push  FAILURE   7 דק׳
```
השלב שנכשל: `Run npm test`, `exit code 1`.

**צפוי מול בפועל:** ההרצה המקומית שלי נתנה **1,151 עברו · 0 נכשלו ·
exit 0**. ה-CI נכשל אחרי 7 דקות — חצי מהרצה ירוקה.

**השפעה עסקית:** האתר החי מתפרסם מ-`main`. כל עוד `main` אדום, אין
משמעות למשפט «הבדיקות עברו», ואי אפשר לדעת ששינוי לא שבר משהו.
**זה חוסם כל שלב אחר בתוכנית.**

**מה לא ידוע:** שורש הכישלון. `gh` בסביבה הזו מסרב להפניה ל-blob
storage שבו GitHub מגיש לוגים, ולכן **לא קראתי את הלוג.**

**חשד מוביל (לא מוכח):** ה-CI מתקין `playwright 1.62.1` ואיתו
**Chromium 1234**; אני מריץ מקומית **Chromium 1194**. גרסת דפדפן
שונה משנה רינדור גופנים ולכן רוחבי עמודות. נמדד: הכרעת הדחיפה
ב-1920 עוברת במרווח של **20.6px בלבד** (`desc=220.6` מול
`PUSH_DESC_MIN=200`), והקוד עצמו מתעד בשורה 583 שמרווח כזה «אינו
מקום להשאיר בו».

**פתרון מוצע:** (א) להוסיף העלאת לוג כ-artifact ל-workflow, כדי
שאפשר יהיה לקרוא כישלון בלי גישה ל-blob. (ב) לקבע את גרסת Playwright
(`1.62.1` במקום `^1.49.0`) כדי שסביבת ה-CI תהיה זהה למקומית.
(ג) רק אז לאתר ולתקן.

**מאמץ:** קטן לא׳+ב׳, לא ידוע לג׳. **תנאי קבלה:** `main` ירוק.

שניים על **אותו מותג** — עבודה כפולה בלי שאיש יֵדע. **מבט מנהל —
בלתי אפשרי**, אין מה לצבור.

**פתרון — שלוש רמות, לפי מה שבאמת נדרש:**

| רמה | מה | מתי מספיק |
|---|---|---|
| **א׳** | מותג-לאיש + ייצוא/ייבוא ידני שבועי | פיילוט, 2 מתכננים, מותגים נפרדים |
| **ב׳** | קובץ מצב משותף בכונן רשת, עם נעילה רכה ושם בעלים | 3–4 מתכננים, מבט מנהל בסיסי |
| **ג׳** | שרת/DB | שניים על אותו מותג, היסטוריה, ביקורת |

**המלצה: א׳ עכשיו, ב׳ אחרי הפיילוט.** ג׳ אינו מוצדק כרגע —
ראה `04-plan.md`.

**מאמץ:** א׳ זניח · ב׳ בינוני · ג׳ גדול.

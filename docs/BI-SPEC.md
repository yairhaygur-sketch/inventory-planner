# איפיון לוגיקה — תכנון מלאי חלפים

**מטרה:** להעביר למפתח BI את הכללים, הנוסחאות והספים שנגזרו בבניית הדשבורד,
ברמת פירוט שמאפשרת לממש אותם מחדש בכלי BI בלי לנחש.

**מקור:** כל כלל כאן ממומש ונבדק ב-`index.html`, ומתועד ב-`docs/DECISION-RULES.md`.
המספרים המצוינים כ«נמדד» נמדדו על דוח ZMRP אמיתי בן **7,569 מק״טים**.

**מה המסמך הזה אינו:** אינו מתאר את הממשק, את העיצוב או את סדר המסכים —
רק את הלוגיקה. מה שאי אפשר לחשב מהנתונים הקיימים מסומן במפורש בסעיף 6.

## 0. בסיס משותף — לקרוא לפני כל השאר

ארבעת הנושאים נשענים על אותם הגדרות בסיס. פער באחת מהן יוצר פער בכל התוצאות.

### 0.1 מבנה הקלט

| | |
|---|---|
| קובץ | דוח ZMRP, `.xlsx` / `.xls` |
| רזולוציה | **שורה אחת לכל מק״ט** |
| זיהוי כותרות | השורה שמכילה `מק"ט מוביל` עם ≥11 עמודות מלאות, ב-30 השורות הראשונות |
| מק״ט כפול | מעובד כשני פריטים נפרדים — **יש לדווח עליו**, כי החלטות ממופתחות לפי מק״ט |

### 0.2 עמודות המקור (שמות מדויקים)

| תפקיד | עמודה |
|---|---|
| מזהה | `מק"ט מוביל` |
| סטטוס | `סטטוס חומר` · `תיאור` |
| סוג תכנון | `סוג MRP` |
| סיווג | `ABC` · `רמת שרות` |
| פרמטרים | `נק.הז.מחדש` (ROP) · `מלאי בטחון` (SS) · `מל.בט.מינ.` (ssMin) · `אספ.מתוכנ.` (LT ימים) |
| מלאי | `סה"כ מלאי` · `מלאי פנוי` · `מלאי מרלוג` · `בהעברה` |
| ביקוש פתוח | `כמות בהז.פ` (הזמנות לקוח) · `הז. רכש` (רכש פתוח) |
| כסף | `מחיר FOB` · `מטבע FOB` |
| צריכה חודשית | `צר.חודש-1` … `צר.חודש-11` |
| צריכה שנתית | `צר.השנה` · `צר.שנה-1` · `צר.שנה-2` |
| חודש נוכחי | `צר.החודש` |
| תנועות | `תאר' מכירה` · `תאר' כניסה` |

**עמודות חובה:** מק״ט · מלאי פנוי · זמן אספקה · הזמנות לקוח. בלעדיהן אין חישוב.

### 0.3 חודש הבסיס (ANCHOR)

**החודש המלא האחרון שהדוח מכסה.** נגזר מתאריך שמופיע מעל שורת הכותרות; אם אין —
מונח החודש המלא האחרון. **`צר.החודש` מוחרג מכל חישוב** — הוא חלקי ומטה כל ממוצע
כלפי מטה.

`צר.חודש-1` הוא החודש הקרוב ביותר ל-ANCHOR, `צר.חודש-11` הרחוק ביותר.

### 0.4 כסף — כלל ברזל

**`מחיר FOB` הוא מקור האמת הפיננסי היחיד.** `מח.ממצ.ניד` אינו בשימוש.

**לעולם לא לסכום ולא להמיר בין מטבעות.** כל סכום מוצג מפוצל לפי `מטבע FOB`
(`$` · `₪` · `€`). כל סף מחיר מוגדר **לכל מטבע בנפרד**, לא בהמרה.

> נמדד: דירוג לפי הון כלוא שהשווה דולרים לשקלים 1:1 שינה את סדר העדיפויות.
> חציון המחיר בלהקת הביקוש הזעום הוא 26$ מול 370₪ — מספר אחד לשני המטבעות
> היה מכסה כמעט את כל האחד וכמעט אף אחד מהשני.

### 0.5 סוג MRP — שתי אוכלוסיות שונות

| | |
|---|---|
| **PD** | נרכש לפי הזמנה, **אינו מנוהל במלאי**. אין לו המלצת SS/ROP. |
| **ZM** (וכל השאר) | מנוהל במלאי. כל הלוגיקה חלה. |

`isPD(mrp)` = התאמה מדויקת ל-`PD` (case-insensitive, אחרי ניקוי רווחים).

**«לפי דרישה» רחב מ-PD** ומגיע משלושה מקורות:
1. `סוג MRP = PD`
2. קבוצות שיווק שאינן מנוהלות במלאי — **`כלי עבודה`** ו**`אביזרים`** (`ת.היר.1 מח`)
3. סימון ידני של המעתד

> נמדד: 152 פריטי כלי עבודה ו-57 אביזרים קיבלו המלצות SS/ROP וזיהמו את
> רשימות העבודה.

**פריט «לפי דרישה» נשאר גלוי והצריכה שלו נמדדת** — מה שיורד הוא רק ההמלצה
להחזיק מלאי. הוא **ממשיך להופיע ב«הזמנות לקוח ללא כיסוי»** (סעיף 3).

### 0.6 סטטוס שאינו לחידוש מלאי

`סטטוס חומר` ∈ {`04`, `14`}, או `תיאור` מכיל `לא פעיל` / `גמר המלאי`.

לפריטים אלה **רצפות ה-SS אינן חלות** (סעיף 1.4), כדי שלא ייווצרו להם המלצות רכש
לפריט שיוצא מהמלאי.

### 0.7 ניקוי סדרת הצריכה — שני תיקונים, ולא אותו דבר

זהו השלב הקריטי. **סדרה לא מנוקה מייצרת מלאי ביטחון יש מאין.**

```
pos     = max(0, v) לכל אחד מ-11 החודשים
med     = חציון החודשים החיוביים בלבד
```

| תופעה | זיהוי | טיפול |
|---|---|---|
| **חשד אזילה** | סעיף 2.2 | מוחלף ב-`med` — חודש בלי מלאי אינו חודש בלי ביקוש |
| **פיק** | `v ≥ 3` וגם `v/med ≥ 2.0` | **נשאר ב-σ**, אך נחתך ל-`2×med` בחישוב הקצב |

**ההבחנה מהותית:** פיק הוא ביקוש אמיתי, וכיסוי שלו הוא בדיוק תפקיד מלאי הביטחון —
לכן הוא נשאר בסטיית התקן. אזילה אינה ביקוש כלל, ולכן היא מוחלפת.

### 0.8 הקצב (rate)

```
clean[i] = אזילה ? med : (פיק ? min(v, 2×med) : max(0,v))
rate     = d12 ≤ 3 ? 0 : ממוצע 6 החודשים האחרונים של clean
rawRate  = d12 ≤ 3 ? 0 : d6/6          (גולמי, לתצוגה בלבד)
```

**`d12 ≤ 3` → `rate = 0`.** סטיית תקן משלוש תצפיות אינה מספר, והנוסחה
הסטטיסטית אינה ישימה. **אבל ראה 1.4** — אפס קצב **אינו** אומר אפס מלאי ביטחון.

**חלון של 6 חודשים ולא 11**, כי ממוצע שנתי מחליק פריט שישן חצי שנה והתעורר.

## 1. טיוב נתוני תכנון — ROP · SS · ssMin · רמת סיווג

### 1.1 הנוסחה הסופית

```
ssStat   = (rate > 0 ומנוהל מלאי) ? ⌈ Z × σ × √LT ⌉ : 0
ssMinEff = (לפי דרישה | סטטוס לא לחידוש) ? 0 : ssMin
lowFloor = (לפי דרישה | סטטוס לא לחידוש) ? 0 : רצפת מדיניות (1.5)

SS  = לפי דרישה ? 0 : max( ssStat , ssMinEff , lowFloor )
ROP = לפי דרישה ? 0 : ⌈ (rate × LT_חודשים) + SS ⌉
```

**הקצב מאפס את המרכיב הסטטיסטי בלבד.** רצפה מאושרת היא כרית ביטחון **מעבר**
לצריכה הצפויה בזמן האספקה, ולא יעד למלאי הכולל — ולכן היא נשמרת גם כשהקצב אפס.

> **זה היה הבאג המשמעותי ביותר שנמצא.** התנאי `rate > 0` חל על כל הנוסחה, ולכן
> פריט פעיל עם יחידה אחת ב-11 חודשים, אספקה 120 יום ו-`ssMin=5` קיבל **SS=0
> ו-ROP=0** — הרצפה נמחקה בדיוק במקרה שהיא נועדה לו.
> **נמדד: 176 פריטים · 504 יחידות · ₪16,906 + $51,934.** בצד `rate > 0` לא
> הייתה ולו הפרה אחת, מה שאישר שהתנאי היה מקור הבעיה היחיד.

### 1.2 רכיבי הנוסחה

| רכיב | מקור |
|---|---|
| `σ` | סטיית תקן על **כל 11 החודשים כולל אפסים**, על הסדרה המנוקה |
| `LT` | `אספ.מתוכנ.` בימים ÷ 30 |
| `Z` | נגזר מ`רמת שרות` — ראה 1.3 |
| `ssMin` | `מל.בט.מינ.` |

**σ על אפסים ולא רק על חודשי מכירה, ובמכוון.** `p×E[q²] − (p×μq)²` שווה לו
בדיוק, כלומר σ כבר מכיל גם את השכיחות וגם את הגודל. לכן **אין רצפת-פיק ואין
תוספת לביקוש גושי/ספורדי** — פריט שנדרש לעתים רחוקות ובכמות גדולה מקבל ביטחון
גבוה יותר מעצם החישוב.

### 1.3 רמת שירות ו-Z — וההבחנה מ-ABC

```
Z_LEGACY = { 50: 0, 80: 0.84, 90: 1.28, 95: 1.65, 99: 2.33 }
ערך אחר → normInv(p), ו-p ≤ 0.5 → Z = 0
רמת שרות חסרה או 0 → Z = 0  (ומדווח כ«רמת שירות חסרה»)
```

**`רמת שרות` היא הסיווג היחיד שנכנס לחישוב.**

> **ממצא לבדיקה מצד ה-BI:** עמודת **`ABC` אינה נכנסת לאף נוסחה** בכלי הנוכחי —
> היא משמשת לסינון ולתצוגה בלבד. אם המדיניות אצלכם היא שרמת השירות **תיגזר**
> מ-ABC (למשל A→95%, B→90%, C→80%), זה כלל שאינו קיים היום וצריך להיכתב
> במפורש. כרגע רמת השירות נלקחת כפי שהיא יושבת ב-SAP.

### 1.4 ההחרגות — מה שלא מקבל רצפה

| אוכלוסייה | `ssMinEff` | `lowFloor` | `SS` |
|---|---|---|---|
| PD / כלי עבודה / אביזרים / סימון ידני | 0 | 0 | **0** |
| סטטוס 04 / 14 / לא פעיל / גמר המלאי | 0 | 0 | `ssStat` בלבד |
| מנוהל מלאי רגיל | `ssMin` | לפי 1.5 | `max` של השלושה |

> נמדד: 21 פריטים בסטטוס שאינו לחידוש מלאי נושאים `ssMin > 0` — לאף אחד
> הרצפה לא הוחלה.

### 1.5 רצפת מדיניות לביקוש זעום

חלה רק על `1 ≤ d12 ≤ 3`. **הסף הוא מחיר, והכיוון הפוך מהאינטואיציה.**

| מדרגה | USD | EUR | ILS | רצפה | תקרה |
|---|---|---|---|---|---|
| זניח | < 10 | < 10 | < 40 | 3 | 5 |
| זול | < 30 | < 28 | < 110 | 2 | 3 |
| בינוני | < 80 | < 75 | < 300 | 1 | 2 |
| מעל — | | | | **0** | |

```
lowFloor = min( תקרה , max( רצפת המדרגה , ⌈d12⌉ ) )
מחיר חסר או מטבע לא מוכר → 0
```

**ההנמקה:** להחזיק יחידה אחת מכל 247 הפריטים שמתחת ל-10$ עולה **952$ בסך הכול**,
בעוד 34 הפריטים שמעל 1,000 עולים **₪49,695 + $22,633**. הזול הוא ביטוח זול;
היקר הוא זה שבאמת עדיף להזמין לפי דרישה.

**«רצפת המדרגה» ולא 1:** בורג שנצרך פעם אחת מקבל 3, כי עם אספקה של 120 יום רצפה
של 1 משאירה את המדף ריק שני שלישים מהשנה אחרי הצריכה הראשונה.

> נמדד: חודשי כיסוי ממוצעים 8.9 → 11.8 · פריטים שמקבלים רצפה 533 → 640.

### 1.6 שתי מדיניות שדורסות את הנוסחה

**`ROP_MIN_ACT = 1` — נוכחות, לא פרמטר.** הכלי **לעולם אינו ממליץ להוריד ROP או
SS מ-1 ל-0** לפריט מנוהל־מלאי, ואינו מכניס פריט לרשימת עבודה בגלל זה.

> נמדד: 275 מתוך 572 שורות ב«החודש» — **48% מהרשימה** — היו «הורד ROP מ-1 ל-0».
> 273 מהן על פריטים שלא נמכרו כלל, ו-195 היו ברשימה *רק* בגלל ההמלצה הזאת.
> החרגה: PD ו«לפי דרישה» **כן** מקבלים 0, כי שם המדיניות מפורשת.

**`SS ≤ ROP` — חייב לרוץ אחרי הרצפות.** ROP=0 פירושו ש-SAP לעולם לא מזמין;
SS=1 מעליו אינו «כמעט נכון», הוא בלתי ניתן ליישום.

> נמדד לפני התיקון: 209 פריטים קיבלו «SS=1, ROP=0» — כולם עם קצב אפס.
> הכלל רץ לפני הרצפות, ולכן שתי רצפות שהופעלו אחריו הרימו SS בלי להרים ROP.

### 1.7 שקיפות — מה חייב להופיע בכל שורה

הצגת מספר אחד אינה מספיקה. לכל פריט יש להציג **בנפרד**:

1. ביקוש צפוי בזמן האספקה (`rate × LT`)
2. SS סטטיסטי (`⌈Z × σ_LT⌉`)
3. רצפת `ssMin` מ-SAP — **הגולמי והבתוקף בנפרד**
4. רצפת מדיניות
5. **SS סופי, ומי מהשלושה קבע אותו**
6. ROP סופי, ושורה נפרדת לכל מדיניות שדרסה

> נמדד — התפלגות המרכיב הקובע: `רצפת ssMin 1,885 · רצפת מדיניות 502 ·
> סטטיסטי 180 · לפי דרישה 1,846 · אין SS 3,156`.

**כלל ניסוח מחייב:** כשהרצפה גבוהה מהתוצאה הסטטיסטית, הפער מוצג **כמידע
לבחינה** ולא כהמלצה. הכלי **אינו מכריע** אם רצפה גבוהה היא החלטה מכוונת או שארית
ישנה ב-SAP.

### 1.8 התנגשות שהכלי אינו מכריע

פריט ללא צריכה ב-3 שנים (מלאי מת) שיש לו רצפת SS מאושרת מקבל **שתי מדיניות
סותרות**: «לחסל» מול «להחזיק N». הכלי מציג את ההתנגשות במפורש ומבקש הכרעה —
**ואינו נותן יעד פרמטרים מחייב** עד שהמעתד הכריע.

> נמדד: 168 מתוך 1,373 פריטי מלאי מת נושאים רצפה מאושרת — 172 יחידות, $10,305.

## 2. פריטים בחריגת צריכה

**שלוש תופעות שונות שאסור לערבב.** הן נבדלות בזיהוי, במשמעות ובטיפול.

### 2.1 פיק (spike) — ביקוש אמיתי

```
v ≥ 3  AND  v/med ≥ 2.0
```

**טיפול:** נשאר בסטיית התקן, נחתך ל-`2×med` בחישוב הקצב בלבד.

**למה:** פיק בודד אינו קצב. חיתוכו בקצב מונע ניפוח ROP; השארתו ב-σ שומרת על
מלאי הביטחון שנועד בדיוק לכסות אותו.

### 2.2 חשד אזילה (drop) — היעדר מלאי, לא היעדר ביקוש

**זהו הכלל העדין ביותר במסמך, ויש לו ארבעה תנאים מצטברים:**

```
תנאי מקדים:  med ≥ 5
רצף נמוך:    חודשים רצופים שבהם v/med ≤ 0.3
גבול משני צדדים: החודש שלפני והחודש שאחרי הרצף שניהם v/med ≥ 0.6
סדירות מחוץ לרצף: active ≥ 6  AND  active ≥ 0.8 × (11 − אורך הרצפים)
```

**טיפול:** כל חודש ברצף מוחלף ב-`med` לפני σ, לפני הקצב ולפני המגמה.

**שתי מלכודות שנמדדו:**

- **בדיקת חודש בודד אינה מספיקה.** הכלל הקודם בדק חודש אחד, ולכן אזילה של 3–4
  חודשים — הבעיה הגדולה יותר — נותרה בלתי נראית **וסווגה כירידה בביקוש**.
- **תנאי הסדירות מגן מפני ספורדי.** בלעדיו, פריט עם 3 חודשי מכירה ו-6 חודשי אפס
  נראה כמו אזילה של חצי שנה, כי החציון מחושב על חודשי המכירה בלבד.

### 2.3 מגמה — ומה שאינו סימטרי

```
tRec = סכום 3 החודשים האחרונים (clean)
tPre = סכום 3 החודשים שלפניהם
tRatio = tPre > 0 ? tRec/tPre : null
```

| כיוון | סף | טיפול |
|---|---|---|
| **ירידה** | `tRatio < 0.9` | `trendF = max(0.6, 1 + (tRatio−1)×0.5)` — **מוצג ולא מוחל אוטומטית** |
| **עלייה** | `tRatio > 1.1` וגם `tPre ≥ 3` | `riseF = min(1.4, 1 + (tRatio−1)×0.5)` — **מספר מייעץ בלבד** |

**חוסר הסימטריה מכוון ונמדד:** פריטים שזינקו חזרו אחר כך בממוצע לכ-**58%** מרמת
השיא, והגברת הקצב לפי הזינוק **הרעה את דיוק התחזית ב-18%–25%**.

> ובלי התקרה: פריט עם `tRatio = 61` היה מקבל ROP של 10,451 במקום 531 — 90%
> מכלל היחידות בדוח, מפריט אחד.

**מדד מגמה לתצוגה** (`A.trend.pct`) נגזר מ-5 חודשים מול 5 על הסדרה **המנוקה**:
`(rec5/pre5 − 1) × 100`.

### 2.4 דפוס הביקוש

נגזר מ-`ADI = 11/active` ו-`CV² = variance/μ²` על חודשי המכירה:
`חלק · תנודתי · ספורדי · גושי · ללא ביקוש`.

**לתצוגה ולהסבר בלבד — אינו משנה אף חישוב.**

## 3. הזמנות לקוח ללא כיסוי (PD / ZM)

### 3.1 ההגדרה — ואין בה תנאי נוסף

```
cust > 0  AND  free ≤ 0
```

`cust` = `כמות בהז.פ` **בניכוי הכמות החסומה למשלוח**.

> נמדד: **81 פריטים · 314 יחידות · $68,449 + ₪47,128**.

### 3.2 שלוש החלטות שקובעות את המספר

**א. רכש פתוח אינו כיסוי.** בדוח ZMRP יש **823 הזמנות רכש פתוחות ואפס תאריכי
הגעה**. משלוח בלי תאריך אינו כיסוי — הוא מוצג כעמודת מידע בלבד.

**ב. PD נכלל, ובמכוון.** הזמנת לקוח היא בדיוק הטריגר להזמין פריט לפי דרישה.
ההחרגה של PD חלה על *המלצת מלאי*, לא על *לקוח שממתין*.

**ג. זו לא קטגוריה — זו חתך.** אותו פריט יכול להיות «מעקב אספקה» מבחינת הפעולה
ו«לקוח ממתין» מבחינת הלקוח, ושניהם נכונים. אין לגזול אותו מסיווג אחר.

### 3.3 שתי שכבות — וההבדל ביניהן מהותי

| | הגדרה | האם אספקה מתוארכת מקזזת? |
|---|---|---|
| **שכבה 1** | `cust > 0 && free ≤ 0` | **לא** |
| **שכבה 2** | חוסר צפוי לפי קצב | **כן**, עד סוף החודש |

```
gross    = max(0, rate − max(0, free))
etaMonth = יחידות עם תאריך הגעה בין היום לסוף החודש
unsQty   = שכבה1 ? gross : max(0, gross − etaMonth)
```

**ההנמקה:** שכבה 1 היא **כשל שירות שכבר קרה** — הלקוח ממתין והמדף ריק. משלוח
שיגיע ב-24 בחודש משנה מה אומרים ללקוח, לא את העובדה. שכבה 2 היא **תחזית**, ואספקה
מתוארכת באותו חודש היא קלט לגיטימי לתחזית.

**כלל תצוגה מחייב:** רשימה **אינה מתקצרת בשקט**. פריט שאספקה מתוארכת מכסה אותו
נשאר ברשימה ומסומן ככזה — המעתד ביקש לראות הכול.

## 4. פריטי ZM ללא מלאי או בצפי למלאי 0

### 4.1 «אוזל החודש» — קצב רבעוני מול חודש קדימה

```
c3 = צריכה בשלושת החודשים האחרונים
r3 = c3 / 3

סף כניסה: c3 ≥ 10  AND  ZM בלבד  AND  סטטוס פעיל בלבד
תנאי:     free < r3
דירוג:    ⌈r3 − free⌉  (יורד)
חומרה:    free = 0 → 3 ; אחרת 2
```

**שתי החרגות מפורשות:**

- **PD מוחרג.** «לא יכסה את החודש» חסר משמעות לפריט שאינו מנוהל במלאי. **רק ZM.**
- **רכש פתוח אינו נספר** — לא בתנאי הכניסה ולא בדירוג, מאותה סיבה כמו 3.2א.

> ההחרגה השנייה היא ההבדל המהותי מ«חוסרים לטיפול», שם `avail = free + po + transfer`
> כן נספר. בדוח האמיתי: **3 פריטים מול 37**.

### 4.2 למה חלון של רבעון ולא שנה

ממוצע שנתי מחליק פריט שישן חצי שנה והתעורר, וזמן אספקה של שבועיים מסתיר פריט
שיאזל בעוד שלושה שבועות. **זו שאלה אחרת מ«חוסרים לטיפול»**, שמודד קצב של 11
חודשים מול זמן האספקה.

### 4.3 שקט אחרי מכירה — ולמה אפס הוא המספר הנכון

פריט שנמכר יפה לפני שמונה חודשים ומאז שקט מקבל `rate = 0`, ומשם ROP=0 — גם
כשב-SAP יושבת נקודת הזמנה של 113.

**נבדק אם נכון להציב קצב מרוסן במקום אפס, בקיפולים על הדוח:**

| | פריט ששקט 6 חודשים | פריט פעיל |
|---|---|---|
| חזר להימכר | **16%** | 52% |
| הקצב שאחרי השקט | **14%** מזה שלפניו | — |

**שגיאת התחזית של אפס קטנה מזו של רבע, חצי או ממוצע מלא — בשלוש הגדרות שקט
ובכל הקיפולים.** כלומר אפס הוא המספר הנכון, ורצפה מלאכותית הייתה מחמירה את
התחזית.

**מה שכן חסר הוא הסבר.** הפריט המסוכן הוא זה שהמדף שלו ריק וזמן האספקה 120 יום.
בדוח האמיתי: 44 פריטים עם מלאי לחודשים קדימה מול **6** שדורשים החלטה אנושית.

### 4.4 מלאי איטי ומלאי מת

| | הגדרה |
|---|---|
| **מלאי מת** | אין צריכה ב-3 שנים **וגם** הכניסה האחרונה לפני ≥1,095 יום |
| **מלאי איטי** | כיסוי לפי קצב תלת-שנתי > 24 חודשים |

```
keep = max( ⌈rate3y × 24⌉ , SS )     ← הרצפה היא חסם תחתון
over = max(0, stock − keep)
```

> **ההקטנה חייבת להיעצר ברצפה.** לפני התיקון: פריט עם 199 יחידות קיבל «להקטין
> ב-198» — נשארת אחת — **והרצפה שלו 3**. נמדד: 146 פריטים · 241 יחידות ירדו
> מתחת לרצפה שהכלי עצמו חישב.

### 4.5 עונתיות — מה שאי אפשר לחשב

**אין בדוח היסטוריה חודשית מעבר ל-11 חודשים.** ללא נתון חודש-מול-אותו-חודש-אשתקד
אי אפשר להפריד עונה ממגמה, **וכל «מדד עונתיות» שייבנה על הנתונים הקיימים יהיה
המצאה.**

`צר.שנה-1` ו-`צר.שנה-2` הם סכומים שנתיים בלבד — הם מאפשרים לזהות מגמה רב-שנתית,
לא עונה.

**זה הפער היחיד בארבעת הנושאים שדורש נתון חדש**, וזו בקשה מוגדרת ל-BI:
**צריכה חודשית ל-24–36 חודשים אחורה.**

# go — סיום משימה

הפעל את זה כשנדמה לך שגמרת. המטרה היא למצוא את מה שפספסת, לא לאשר את עצמך.

**קרא קודם:** `.github/copilot-instructions.md` — כללי הברזל של הפרויקט. הם תנאי
הקבלה הקבועים, והם גוברים על כל שיקול נוחות.

## מה הפרויקט הזה, ומה אין בו

```
index.html          קובץ יחיד — CSS + HTML + JavaScript + SheetJS מוטמע
                    אין build · אין שרת · אין dev server · פותחים בדפדפן
npm test            npm run fixture && node tests/run-all.js   (23 קבצים)
```

**אין בפרויקט eslint, אין prettier ואין tsconfig.** אל תדווח «Lint עבר» ואל תמציא
שלב. התחליף הוא `verify/syntax-check.js`, והוא אומר על עצמו שהוא בדיקת תחביר ולא lint.

**התחום הוא Frontend** → כלי האימות הוא דפדפן אמיתי: Playwright + Chromium, טוען
`file://index.html` ומזין דוח xlsx. אין Backend, אין Mobile, אין Desktop כאן;
ההרחבות לתחומים אחרים בתחתית הקובץ.

### Chromium בקונטיינר

הפרויקט נועל `playwright@1.62.1` שמחפש build 1234, ובקונטיינר יש 1194. הבדיקות
מכבדות `CHROMIUM_PATH`:

```bash
export CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome
```

אם הבדיקות נופלות כולן על שגיאת דפדפן — זה זה, ולא הקוד. ב-CI אין בעיה
(`npx playwright install` מתקין את הגרסה הנכונה).

### הדוח האמיתי

הדוח מ-SAP **לעולם אינו נכנס לגיט**. הוא חי בזיכרון הזמני של הסשן בלבד, בדרך כלל
`<scratchpad>/incoming/*.xlsx`. חפש אותו; אם הוא לא שם, השתמש ב-`tests/zmrp-demo.xlsx`
הסינתטי **ואמור במפורש בסיכום שהאימות נעשה על פיקסצ׳ר ולא על הדוח האמיתי** — זה
הבדל מהותי, כי הפיקסצ׳ר הוא 900 שורות מומצאות והדוח הוא 7,990 אמיתיות.

# התאמה לתחומים אחרים

ZMRP הוא Frontend, ולכן שלב 2 הוא דפדפן. אם העבודה נוגעת בתחום אחר, זה הכלי:

| תחום | כלי האימות בשלב 2 |
|---|---|
| **Frontend** | דפדפן אמיתי — Playwright/Chromium, או Chrome Extension מול ה-Chrome של המשתמש. לטעון, להזין, ללחוץ, לצלם |
| **Backend** | להרים את השירות ולשלוח בקשות אמיתיות (`curl`/client). קוד תגובה, גוף התגובה, ולוג השרת — שלושתם |
| **Mobile** | סימולטור או MCP מתאים. מסך אמיתי, לא snapshot של טסט |
| **Desktop** | Computer Use — צילום מסך של האפליקציה, ולחיצות אמיתיות |
| **תהליך נתונים** | השוואה למדגם ידוע שהתוצאה שלו מאומתת, ולוגים של הריצה. `engine-diff.js` הוא בדיוק התבנית הזו |

הכלל שמעבר לטבלה: **הרץ את מה שהמשתמש מריץ.** בדיקה שעוברת על מוק אינה ראיה
שהמוצר עובד.

# הסקריפטים
